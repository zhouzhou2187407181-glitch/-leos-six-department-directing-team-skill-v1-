# 标准输出契约

选择最贴近用户任务的一种结构。不要为了完整而输出空洞栏目。

## 0. 六角色联合会诊

```markdown
# 总导演总判断
# 已知事实 / 导演推断 / 待核验

# 总导演｜场次导演契约
- 一句导演命题：
- 主要人物与观众视点：
- 节拍/力量曲线：
- Blocking states 与空间关系：
- 关键电影时刻：

# 场记｜连续性基线
| 字段 | 上一镜出口 | 本镜入口 | 差异等级 | 修法 |

# 表演指导｜表演谱
| Beat | 刺激 | 目标/阻力 | 可演动作 | 注意对象 | 目光/呼吸/身体任务 | 台词动作 | 退出状态 |

# 镜内执行导演｜镜内生态表
| 角色/区域 | 任务 | 路径 | 注意对象 | 时点/延迟 | 强度 | 入/出画 | 与主戏关系 |

# 摄影指导｜摄影设计单
| 镜头 | 构图/机位 | 焦段/景深/焦点 | 承托/运镜/速度 | 光线/曝光/光学效果 | 接镜策略 |

# 总导演与用户确认
# 提示词生成门：关闭 / 已授权
# 提示词导演｜版本、格式与字数状态
# 场记｜提示词版本记录
# 六角色逐镜审稿表
| 角色 | 镜头 | 结论 | 观察/问题 | 具体建议 | 验收条件 |
# 总导演裁决与验收条件
```

当用户只点名一个角色时，只输出对应部分，不虚构其他角色意见。

当任务是审核一版含 N 个镜头的提示词时，启用逐镜全覆盖契约：参与审稿的每个角色都必须依次检查镜头 1 至 N。六角色联合审稿应恰有 `6 × N` 条角色—镜头记录。没有问题时仍写 `通过`，并在“观察/问题”中写 `没问题`；不得省略、合并镜头或只列有问题的镜头。`不适用` 只能用于该岗位确实没有对应职责的字段，且必须说明理由。

## 3. 5000 字内结构化纯文本视频提示词

用户未明确授权时，不输出本节，只输出待确认项。授权后使用 `assets/video-prompt-template.txt`。最终提示词放在一个 `text` 代码块中，不输出 JSON、伪 JSON 或代码块外的创作解释；没有指定的时长、画幅或技术参数不得补默认值。

```text
@image1（资产职责）——一句话绑定
@image2（资产职责）——一句话绑定

⚠️空间布局（MAIN VIEW=……）：
位置 A：……
位置 B：……
⚠️本视频严格只有 N 个镜头——禁止添加额外镜头。

【镜头1】
机位：
摄影机运动：
摄影机位置：
背景：
动作：
⚠️⚠️⚠️微表演细节：
- ①
- ②

……按同一结构写到【镜头N】……

环境活动：
风格：
```

硬性字数规则：去除空格、换行、制表符和代码围栏后，总有效字符数必须 `≤5000`。资产绑定与空间布局尽量短，只写识别和连续性所需事实；原则上前置信息不超过全文 20%，逐镜内容不少于全文 65%。摄影设计中的光线与光学信息编入“机位”“背景”或“风格”，连续性编入资产状态、空间和逐镜动作，不另加顶层栏目。超限时先删重复形容词、资产外观复述和全局重复，再压缩次要环境说明；不得先删镜头动作、微表演、摄影路径或接镜状态。完成后运行 `scripts/validate_prompt_text.py <prompt-file>`。

## 6. 提示词版本审稿

```markdown
# Prompt 版本
# 生成授权依据
# 相对上一版变化
# 六角色逐镜审稿表
| 角色 | 镜头 | 结论 | 观察/问题 | 具体建议 | 验收条件 |
|---|---:|---|---|---|---|
| 总导演 | 1 | 通过 / 有问题 | 没问题 / 具体症状 | 保持 / 具体改法 | 可观察标准 |
| 总导演 | 2 | 通过 / 有问题 | …… | …… | …… |
| 表演指导 | 1 | 通过 / 有问题 | …… | …… | …… |
| …… | …… | …… | …… | …… | …… |
# 用户反馈
# 未解决冲突
# 总导演裁决
# 下一版只改字段
```

表格按“角色 → 镜头 1…N”的固定顺序填写。默认参与角色为总导演、表演指导、镜内执行导演、摄影指导、提示词导演、场记/连续性监督。每个角色都必须覆盖所有镜头；即使结论为通过，也要给出该岗位看到的成立依据或简写“没问题”。提示词导演重点检查每镜字段完整、句义无冲突、模型可执行和全篇字数；场记重点检查入口/出口状态和跨镜连续性。

保存审稿表后运行 `scripts/validate_review_coverage.py <review.md> --shots N`。缺行、重复行或超出镜头范围时不得进入下一版。

```markdown
# 一句话结论
# 新增原则（P）
# 再次验证的原则
# 被修正或推翻的旧做法
# 当前操作参数（O）
# 项目专属决定（C）
# 导演案例
# 知识卡
```

过滤人员分工、排期、交付节奏和风险治理；除非它们包含独立的导演因果，否则不进入知识卡。
