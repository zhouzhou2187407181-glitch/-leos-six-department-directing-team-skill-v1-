## 1. 提示词导演的共同语境

不要只把对白交给语言模型自动分镜。先提供：

- 场次上下文与前后因果；
- 角色身份、当前目标和关系；
- 权威场景及空间锚点；
- master、轴线和主观人物；
- 已有连续性状态；
- 项目画面与声音规范；
- 人类导演的调度意图。
- 表演指导、镜内执行导演与摄影指导已经确认的设计；
- 用户本轮意见、项目风格档案和提示词生成授权。

提示词导演负责结构化、查漏和清晰表达，不把叙事价值判断外包给它。用户未明确开启生成门时，不输出最终提示词。

## 2. 纯文本模板与字数预算

使用 `assets/video-prompt-template.txt` 和 `prompt-director.md`，按以下顺序组织提示词：

```markdown
资产绑定
空间布局与镜头总数
【镜头1】至【镜头N】
  机位 / 摄影机运动 / 摄影机位置 / 背景
  动作 / 微表演细节
环境活动 / 风格
```

“电影感”“紧张”“高级”等词必须落实成可观察条件。每个复杂镜头写清摄影机在哪一侧、主体朝向、动作路径、摄影机路径和结束构图。

最终输出是中文纯文本，不是 JSON。时长、画幅、帧率、分辨率只在用户或项目明确时写入对应自然语言字段；未明确时省略。禁止补固定兜底值。

每版提示词去除空格、换行、制表符和代码围栏后的有效字符数必须 `≤5000`。建议预算：资产绑定与空间布局合计 `≤20%`，逐镜内容 `≥65%`，环境活动与风格约 `15%`。资产只写身份、职责和必须继承的识别特征；空间只写会影响调度、视线和接镜的锚点。摄影设计中的光线、曝光和光学效果写入“机位”“背景”或“风格”；连续性写入资产状态、空间关系和逐镜动作。若超限，依次压缩重复形容词、资产外观复述、全局重复和次要环境细节，不先牺牲每镜动作、微表演、摄影路径和出口状态。

生成后保存为纯文本文件并运行 `scripts/validate_prompt_text.py <prompt-file>`。校验未通过时不得交付或进入视频生成。

若模型持续忽略字幕、音乐等禁止项，可把高优先级禁止项移到资产绑定之后再复测；不要假定所有模型都对提示词末尾保持同等注意。

## 3. 镜头数与生成段落

镜头数由节拍、信息密度、表演呼吸、摄影运动和目标模型能力决定。固定镜头数或固定时长不能作为规则。慢表演可少镜头，快速动作可多镜头。

一条生成尽量只使用一个场景参考。室内外、楼上楼下或明显不同空间分开生成，避免多场景资产互相污染。

复杂段落按稳定的空间关系或戏剧小节分组，不把整场“一坨生成”。每组内部应有可用的建立、动作和反应，不要求完整使用所有秒数。

互动分支分别生成。主动进入与抗拒后被推入会改变动作顺序、座位、身体状态和情绪，不用一条模糊镜头同时覆盖多个选择。

## 4. 跨段接缝

为相邻生成段设计重叠覆盖区：下一段可从上一段接近结尾的姿态、动作或空间关系开始，留给剪辑选择。保持人物位置逻辑相似，但让景别或角度有足够差异，避免硬跳切。

可使用上一段落幅、提取帧或文字化空间描述作为连续性资产。不要假定模型理解“续拍”；明确写出上一段结束状态和下一段进入状态。

## 5. 重试与模型选择

第一次生成可以探索。失败后先分类：

- 空间/方向错误；
- 资产职责冲突；
- 表演或节奏错误；
- 物理/动作错误；
- 画质劣化；
- 模型能力边界。

第二次必须改变条件：修正 master、净化参考、补充摄影机侧、拆短动作、改成反应镜头或换更适合的模型。不要用同一条件连续抽卡。

按镜头需求选择模型，而非绑定单一平台。高成本模型只在复杂度和预期收益匹配时使用。价格、可用率、最长秒数、分辨率和重试次数均属 O 类参数，注明 `valid_as_of` 并定期复测。

## 6. 素材卫生和声音

每次生成后检查是否出现噪点累积、塑料皮肤、错误反光、脏高光、角色混入和字幕。只需要构图时不要把低质成图继续传代。

声音要区分：现场环境声、动作声、对白、临时模型声音和后期音乐。通常禁止模型自加音乐；声音连续性不足时明确标注为后期统一项，不让错误声线影响对画面表演的判断。

把生成结果尽快放入时间线。只保留真正有用的区间；后半段好就只用后半段，缺一个反应就只补一个反应。

## 7. 生成前检查门

送入模型前逐项确认：

1. 台词评价的变化是否已有可见前因；
2. 大全景的人物、门、车和建筑比例是否可通过现实测试；
3. 近景是否继承 master 的位置和摄影机侧；
4. 每个可见角色是否有不同任务、时点和强度；
5. 关键道具/动作是否写明初始、变化和结果状态；
6. 人物是否会响应环境光区；
7. 角色名是否与正确参考图和文字特征绑定；
8. 背景文字、镜像、字幕和音乐限制是否明确。

## 8. 表演提示与可归因迭代

表演提示先从 `performance-direction.md` 的表演谱提取主体动作和时间链。优先写：人物位置与真实任务 → 刺激 → 反应延迟 → 可演动作 → 少量微行为 → 退出状态。不要把“悲伤、复杂、内心挣扎”当成模型可执行动作。

使用直接、正向、简单的描述。输入图已负责外貌、构图和光线时，文本重点描述主体动作、摄影机运动和环境运动，避免重复描述资产已确定的信息。

重试时保存上一版，明确本次唯一主要变化。一次只改主体动作、时间关系、镜头运动、环境动作、参考资产或模型中的一类；组合改动必须标记为不可单独归因。提示词每版先写入 `assets/prompt-version-log-template.csv`；生成结果再关联到 `assets/take-prompt-log-template.csv`。
